# 训练用题面 / I/O 约定（code/spec.md）

> 这不是九坤原题。原题以你拿到的 PDF/邮件为准；本文件只固定**训练格式**，
> 方便你的程序、oracle、stress 三方对齐。规则参数都做成可配置，原题一到，
> 改 `goal_row` / `k` / `no_move` 三处即可。

## 1. 输入

```
n m
k1 k2
< n 行，每行 m 个字符 >
```

字符：`.` 空、`#` 障碍、`b` 黑棋、`w` 白棋。

## 2. 输出

一行：`WHITE` / `BLACK` / `DRAW`（双方最优策略下的结果）。

调试模式 `--moves`：先输出一行表头，再每行 `fr fc tr tc win`：

```
# from_r from_c to_r to_c win
1 1 2 1 1
```

`win=1` 表示这一步直接结束游戏（吃子或黑棋突防）。

## 3. 规则开关（默认值）

| 参数 | 默认 | 含义 |
|---|---|---|
| 先手 | 白 | `state.turn = 0` |
| 方向顺序 | 下、左、右、上 | `DR/DC` |
| 黑可用方向 | 前 `k1` 个 | `1 <= k1 <= 3` |
| 白可用方向 | 前 `k2` 个 | `1 <= k2 <= 3` |
| `goal_row` | `n-1`（最下面一行） | 黑棋走到该行立即胜 |
| 无合法走法 | 判负 | 改成 `draw` 需同时改 oracle 和你的程序 |
| 吃子 | 立即胜，游戏结束 | 不需要“翻转” |
| 循环 | 双方都无法强制取胜则平局 | 精确解由 retrograde 得到 |

> **为什么默认 `goal_row = n-1`**：若按“第 1 行 = 最上面一行”，黑棋只能靠
> “上”突防，而“上”是第 4 个方向、`k1 <= 3` 取不到 —— 规则自相矛盾。
> 最自然的解释是“行号从下往上数，第 1 行 = 最下面一行”，黑棋向下冲。
> 面试时先把这个歧义问清楚（详见 `04_othello.md` 第 0 节）。

## 4. 样例（可直接对拍）

### 样例 1 —— 黑棋踩子

```
3 3
3 3
...
.b.
.w.
```

白先。白只有下/左/右（无上），够不到黑；黑向下走一格踩到白。
答案：`BLACK`。

### 样例 2 —— 白棋堵死黑棋

```
3 3
1 1
.w.
...
.b.
```

白先向下走一格；黑只能向下，已在底行，无路可走判负。
答案：`WHITE`。

### 样例 3 —— 平局

```
3 3
3 3
..b
..w
...
```

双方都能永远躲开对方，谁也无法强制取胜。
答案：`DRAW`（31 个可达状态，13 胜 / 9 负 / 9 平）。

### 样例 4 —— 黑棋突防

```
3 3
1 1
w..
.b.
...
```

白向下，黑向下到 `goal_row`，立即获胜。
答案：`BLACK`。

## 5. 命令

```bash
python3 oracle.py --file case.txt --stats        # 精确解 + 状态数
python3 oracle.py --file case.txt --moves        # 初始局面全部走法（白/黑两段）
python3 oracle.py --selftest                     # 两套算法互验

g++ -O2 -std=c++17 -Wall -Wextra stub.cpp -o stub
./stub < case.txt
./stub --moves < case.txt

python3 gen.py --n 4 --count 20 --out cases
python3 stress.py --bin ./stub --count 100 --moves
python3 stress.py --bin ./stub --count 100
```

## 6. oracle 的边界

- 状态数 ≈ `2 * C(空, 黑子) * C(余, 白子)`；4x4 各 2 子约 2 万，5x5 各 2 子约 17 万，再大就慢。
- `--max-states`（stress 默认 20 万）会自动跳过过大的用例。
- oracle 只用于**小棋盘对拍**；10x10 的正确性靠规则单测 + 不变量 + 抽样。
